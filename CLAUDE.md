# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Aiva is a voice AI companion for Windows: a fully streaming voice pipeline (pipecat 1.5.0) with her own Live2D desktop avatar (self-rendered — no VTube Studio), native LLM tool calling, long-term memory, an ambient wake-word mode, and a desktop pixel cat. Everything she says is spoken aloud via TTS — tool results, prompts, and persona text must be short spoken prose (no markdown, emojis, or lists).

## Versioning

Her version lives in `aiva/version.py` (`__version__`, started at **0.9.0** on 2026-08-28; 1.0.0 = the selfhood/speaker/affect wave validated in real use). It's printed at boot, logged, and shown in the dashboard subtitle. **When you make a notable change, add a bullet under `[Unreleased]` in `CHANGELOG.md`** (Keep a Changelog format); cut a version by moving those bullets into a dated section and bumping `version.py` (SemVer: patch=fix/tune, minor=new capability, major=1.0+).

## Commands

- **Python**: 3.11.9 via `.venv` (pyenv-win manages `.python-version`). Always use `.venv\Scripts\python`.
- **Install deps**: `.venv\Scripts\pip install -r requirements.txt`
- **Run Aiva only**: `cd aiva && ..\.venv\Scripts\python main.py` (she spawns/adopts her avatar renderer herself)
- **Run with OBS**: `cd aiva && ..\.venv\Scripts\python launcher.py` (boots OBS unless `--no-obs`, then imports main)
- **Full production launch**: `start_aiva.bat` (ambient wake-word mode + restart loop; relaunches on exit code 42)
- **List audio devices**: `cd aiva && ..\.venv\Scripts\python main.py --list-devices`
- **Avatar renderer demo (never starts Aiva)**: `cd aiva && ..\.venv\Scripts\python -m modules.avatar_renderer --demo` (also `--windowed` for GL triage, `--selftest` for a 3 s smoke)
- **Avatar client probe (never starts Aiva)**: `cd aiva && ..\.venv\Scripts\python -m modules.avatar --probe`
- **Cat demo (never starts Aiva)**: `cd aiva && ..\.venv\Scripts\python -m modules.cat --fast`
- **Dashboard (never starts Aiva)**: `cd aiva && ..\.venv\Scripts\python dashboard.py` (live read-only web view of her state at http://127.0.0.1:8760 — mood/diary/wishes, traits, books, tasks, flows, facts, cat, capabilities, and a Statistics operations profiler; `--once` prints one JSON snapshot, `--open` opens the browser; stdlib-only, safe while she's running)
- **Regenerate cat sprites**: `cd aiva && ..\.venv\Scripts\python -m modules.cat_sprites`
- **Tests** (offline, fast): `.venv\Scripts\python -m pytest tests -q` — covers the task runner and task memory with a scripted fake LLM, fake tools and an in-memory sqlite. No linter configured.
- **Semi-live task runner check (real OpenAI + real tools, never starts Aiva)**: `cd aiva && ..\.venv\Scripts\python ..\tests\e2e_task_runner.py "<goal>" [--yes]`

**Do not start, stop, or restart the live Aiva process yourself** — the user manages her lifecycle. Code changes are picked up when the user restarts her (hot reload is not a thing here). `training/` is a separate offline wake-word training project with its own venv and multi-GB data files; leave it alone unless asked.

Config lives in `.env` at the repo root and is loaded with `load_dotenv(override=True)` — it beats any same-named variable inherited from the launching shell (a stale `AIVA_LLM_MODEL` in the environment once made a `.env` model change a silent no-op) (API keys, `AIVA_LLM_MODEL`, `AIVA_WAKE_WORD`, device indices/names — see README). Runtime event logs go to `aiva/logs/aiva-YYYYMMDD.log` via `log_event()`; that file is the place to look when diagnosing something that happened hours ago (wake/sleep transitions, wake-word scores, what she heard, announces).

## Architecture

The streaming pipeline is assembled in `aiva/main.py`:

```
transport.input → MicController → Deepgram STT → ActivityWatcher → user aggregator
(Silero VAD + local smart-turn v3) → OpenAI LLM (native tools) → ProcessingWatcher
→ ElevenLabs TTS → LipSyncTap → UsageTracker → transport.output → assistant aggregator
```

- `aiva/main.py` — pipeline assembly, hotkeys (F9 mute = full **deafen**: zero-fills the STT path AND makes `wake()` ignore any wake with a preroll/verify, so the wake word can't wake her while muted — her own preroll-less announces still can, so she can speak up deafened; F10 interrupt, Ctrl+Alt+R restart, Ctrl+Alt+X quit), ambient wake-word listener (openWakeWord on its own mic thread), idle/sleep management, restart machinery, session persistence at shutdown.
- `aiva/modules/library.py` — pure, sqlite-free, thread-safe book readers: EPUB (stdlib zip+XML+html.parser), TXT/MD (decode chain + Project Gutenberg strip), PDF (pypdf; scan detection, running-header removal, de-hyphenation, outline→chapters). `parse_file` → ordered `Section`s; `segment`/`normalize_sections`/`chunk`. Runs under `asyncio.to_thread`; `clean_text` normalises whitespace ONLY so copied quotes verify verbatim.
- `aiva/modules/reading.py` — `BookMemory` (7 tables on `Memory.conn`) + `ReadingEngine`. One background reading *session* at a time (`llm.create_task`): per section a close-reading note (summary/key ideas/exact ≤25-word quotes VERIFIED against the text/nuances/reflection/running summary+state), `commit_section` moves the cursor atomically with the note (kill mid-section → redo that section, never a dup), session wrap → "what struck me", whole-book synthesis on finish (own model), embedding `recall`. Announces via injected callbacks (quiet while asleep). Hooks `on_section/on_session_end/on_book_finished/on_book_added` feed becoming.
- `aiva/modules/becoming.py` — how reading changes her: `reading_lessons`, `traits`, `voice_notes`, `becoming_state` on `Memory.conn`. On book finish, one JSON call extracts candidates; `validate_candidates` (pure) enforces first-person, evidence-in-notes, bounded content, and baseline-contradiction rejection; `adopt` caps trait strength 0.7 / 12 active, dedupes+reinforces, `fade`s unused ones; tell-once rides the finish note; `drop_trait` vetoes permanently; `reading_permission` + the pure `curiosity_decision` govern when she asks to read. `prompt_blocks` renders the four persona blocks. `python -m modules.becoming --show` audits her.
- `aiva/modules/inner.py` — her **nervous system** (substrate for the selfhood work, `docs/PLAN-selfhood-and-eval.md`). Phases 1–2 built & offline (**NOT yet wired into `main.py`** — no live effect until then): `InnerState` (valence/arousal/social/focus dials, persisted to `aiva/inner_state.json`, decays toward an env-set baseline like the cat), `InnerBrain` (PURE: `decay`/`integrate` with a salience-gate + material-change flag, `now` always injected), `ExperienceBus` (`experience` table on `Memory.conn`; `emit`/`drain`/`mark_consumed` — the shared bloodstream that replaces point-to-point hooks), and `SelfEngine` (`journal` + `desires` tables; `tick` drains the bus → moves mood → when earned writes a private diary entry via `JOURNAL_PROMPT` on the side model + forms desires deduped/vetoable like traits; `should_journal`, `add_desire`/`drop_desire`/`recall_journal`). Journal is her inner voice, NEVER announced. The dashboard reads all of it (mood dials, experience stream, diary, wishes). **Wired live in `main.py` (Phases 2–3 core):** the self loop `self_watch` ticks every `AIVA_SELF_TICK_S`; reading emits `chapter_read`/`book_finished` (mood-hinted by the note's feeling) and time emits `daypart`; mood + open wishes render as the HOW YOU FEEL / WHAT YOU FIND YOURSELF WANTING persona blocks (refreshed on material mood change via `refresh_system_prompt`); voice tools `note_desire`/`drop_desire`/`recall_journal`/`set_initiative`; a private diary entry is forced at shutdown (digesting recent conversation). **Phase 4 (initiative) shipped:** the pure `initiative_decision` (mood + presence + backoffs/caps/quiet-hours/boot-grace) drives `initiative_tick` in `self_watch` so she can `express` a feeling or `ask` about an open wish on her own. **Phase 5 (autonomous action) shipped:** `initiative_decision` now also returns `"act"`, and `initiative_tick`→`_do_act` pursues a wish herself via an injected `_act(desire)` dispatcher — but ONLY when the injected `actionable(desire)` predicate approves it (auto-tier via `capabilities.match`, not paused; wired in `main.py` as `_self_actionable`→`_act_on_wish`, v1 = find-and-keep an image to her space, gated by `AIVA_SELF_ACT` + a tighter `max_acts_per_day` + the `ServiceLimits` Tavily cap). The wish is consumed (`status='acted'`) and a `self_act` event is emitted (learn-by-doing) BEFORE dispatch. Anything that spends/sends/touches his files/edits her code stays an `ask`. `set_initiative(always|ask|quiet|never)` is the switch, tracked in a `self_kv` table. **Emitters MUST run on the event-loop thread** (sqlite conn rule) — so the cat's autonomous changes (tk thread), per-turn conversation sentiment, and avatar-expression-from-mood are the Phase-3/4 tail. `python -m modules.inner --show` audits her. Tests: `tests/test_inner.py`, `tests/test_self_engine.py`, `tests/test_initiative.py`, `tests/test_persona.py`.
- `aiva/modules/preferences.py` — her **mutable likes/dislikes/opinions**, distinct from `becoming` (which is reading-only and forbidden from contradicting the baseline). `Preferences` store (one `preferences` table + a `pref_kv` on `Memory.conn`) with SIGNED `valence` (magnitude=conviction, sign=like/agree vs dislike/disagree), `kind` taste|opinion, `origin` baseline|reading|conversation|reflection, deduped by subject embedding (cosine 0.86 / jaccard 0.60 fallback), capped (`MAX_ACTIVE`=24, `ADOPT_CAP`=0.6 so one event can't create a strong pref), faded (half-life 120d / 240d baseline, floor 0.2, every ~20h) and permanently vetoable (`drop`). The coherence guard is **inertia, not a veto**: the PURE `evolve(valence, evidence, origin, direction)` reinforces toward the extreme on same-direction evidence and *erodes toward 0 first* on opposite evidence — flipping only after sustained counter-experience, and ~2× slower for `origin='baseline'`. `seed_from_baseline()` (run once at boot) seeds her frozen tastes as `baseline`-origin rows; from then on they evolve like any other. `apply()` is async (embeds), returns inserted|reinforced|eroded|flipped|blocked|rejected; `_BOUNDED` rejects harmful content. Formation piggybacks `SelfEngine._digest` (the `preferences` key in `JOURNAL_PROMPT` — NO extra LLM call); `SelfEngine(preferences=…)` applies each delta. Rendered as the "WHERE YOU STAND" persona block (`prompt_block` → likes/dislikes/opinions, refreshed on change); voice tools `note_preference`/`drop_preference`. The PERSONALITY split moved *tastes* here and left *temperament/voice* frozen, so `persona.baseline_traits()` (becoming's anti-contradiction gate) now protects character only. `python -m modules.preferences --show` audits. Tests: `tests/test_preferences.py` (+ formation in `tests/test_self_engine.py`, split in `tests/test_persona.py`).

## Non-obvious constraints (learned the hard way)

- **Windows audio capture must run at the device's NATIVE sample rate.** Asking for 16 kHz directly yields silence (MME) or corrupted buffers (DirectSound). `MicController` resamples to the 16 kHz that VAD/STT need and re-stamps the StartFrame. Device selection prefers MME host API. The wake-word listener does the same dance independently.
- **Self-hearing gate**: while Aiva speaks (+0.5 s cooldown) mic audio is zero-filled *before* STT so she can't transcribe herself; `AlwaysUserMuteStrategy` is the second layer. Voice barge-in is deliberately disabled — F10 is the interrupt.
- **Ambient mode economics**: while asleep, `MicController` *drops* audio frames entirely so Deepgram receives (and bills) nothing. Pipecat's built-in worker idle timeout must stay `None` — with frames dropped, its default 300 s monitor would silently kill her.
- **Wake word is two-stage**: the custom `hey_aiva.onnx` model fires on TV/game speech with the same scores (up to 0.96) as real wakes, so a wake-word hit is only a *candidate*. `WakeWordListener` passes a 2.5 s pre-roll; `MicController` injects it ahead of live audio and holds the wake as provisional (`verifying`, `visibly_awake` False — eyes stay shut); `ActivityWatcher` confirms on the first final transcript containing her name (`mentions_name`) or rejects and puts her back to sleep, dropping the transcript before the LLM. Don't "simplify" this back to trusting the model score — see the `wake rejected` lines in the logs for what it filters.
- **Restart machinery**: `restart_self`/Ctrl+Alt+R exit with code 42; `start_aiva.bat` relaunches (or a detached watcher process does if she wasn't started via the bat). `.restart_marker` tells the next boot to say "I'm back" instead of a full intro. The avatar renderer stays up across restarts — the new process adopts it via `aiva/avatar_state.json`; only a real quit kills it.
- **Lip-sync timing**: TTS audio frames pass `LipSyncTap` FASTER than real-time (the output transport paces playback). RMS chunks are queued in the renderer with durations and consumed at wall-clock rate from `BotStartedSpeakingFrame`. Flush only on `InterruptionFrame` — flushing on `TTSStoppedFrame` (end of *generation*) would close her mouth mid-sentence every turn.
- **PyQt5, not PyQt6/PySide6**: the renderer's transparent window depends on it — Qt6 bindings have a known black-background bug with `WA_TranslucentBackground` + OpenGL (live2d-py issue #98).
- **Shell command safety is non-bypassable**: `run_command` only *stages* a command; execution requires the user's verbal confirmation followed by `confirm_pending_command`. Keep this two-step gate intact. The task runner obeys the same rule from the other side: a `shell` step pauses the task (`awaiting_user`, kind `confirm_command`) until `answer_task` brings a yes, and only then calls `tools.execute_shell` — the single place a command actually runs. `run_command`/`confirm_pending_command`/`claude_code` are deliberately NOT in `RUNNER_TOOL_ALLOW`.
- **Reading is greenfield and cost-bounded**: study/synthesis run on `AIVA_STUDY_MODEL`/`AIVA_STUDY_SYNTH_MODEL` (default luna/terra — their OWN tokens-per-minute bucket, never the voice model); per-session and per-book (`AIVA_BOOK_MAX_COST_USD`=3) caps; a novel costs ~10-25 cents. `library.py` imports no sqlite (parse in a thread, write on the loop); `commit_section` is the ONLY place the book cursor moves, atomically with the note; quotes are verified verbatim ≤25 words and never enter the prompt. Books resume from a persisted cursor (they are NOT runner tasks); `book_memory.reconcile_stale()` only marks the in-flight session interrupted.
- **Reading changes her within bounds**: the static `PERSONALITY` traits are the floor; a book may deepen or add a facet, never contradict it (compatibility gate) — traits cap at 12, fade if unused, and a voice `drop_trait` removes one forever. Tell-once is announced-at-injection (rides the book-finish note); the four persona blocks all carry the anti-recite rule so she never lectures or quotes unprompted. Curiosity thresholds live in `becoming.CURIOSITY` and are tunable from the `becoming:`/`read:` log lines; `_user_present` uses Win32 GetLastInputInfo so she only asks to read when you're at the PC but quiet.
- **Task autonomy is experience-based by design** (user decision 2026-08-25): done-this-kind-of-thing-before → just do it with a one-line heads-up; novel, previously corrected, irreversible, shell or delegate → confirm first; options only when the planner flags genuinely different approaches. The voice LLM may be MORE careful than `decide_autonomy` says, never less. Don't re-tune the thresholds without checking `familiarity:` lines in the logs.
- **`answer_task` must find the task already waiting**: `TaskRunner._prepare_wait` puts a task into `awaiting_user` BEFORE `start_task` returns its in-turn question, because the user's yes can arrive in the same voice turn. Don't reorder that.
- **OpenAI tokens-per-minute is the scarce resource** (org is on the 30k TPM tier for gpt-4.1 as of 2026-08-26). Each voice turn re-sends the whole context + ~5.5k tokens of tool schemas + ~3.8k of system prompt. Keep side-calls OFF the voice model: `AIVA_TASK_MODEL` and `AIVA_VISION_MODEL` default to gpt-4.1-mini in `.env` (own bucket); `PatientOpenAILLMService`/`AIVA_LLM_MAX_RETRIES` make 429s a backoff instead of a dead turn; `trim_context()` (every 15 s in `flush_transcripts`, budget `AIVA_CONTEXT_BUDGET_CHARS`=24000) keeps history bounded — it saves transcripts first and calls `memory.forget_saved()` so persistence stays consistent, and never drops in-flight tool exchanges. Don't add per-turn LLM calls on the voice model without checking this.
- **Models are gpt-5.6-luna everywhere by default (voice, tasks, vision) since 2026-08-26** — 500k TPM at tier 1, ~$0.20/$1.20 per 1M, sub-second first token. The gpt-5.x line has a different Chat Completions shape: `max_tokens` is rejected (use `max_completion_tokens`) and function tools REQUIRE `reasoning_effort: "none"` (default effort → 400). Every direct OpenAI call goes through `utilities.llm_kwargs(model, max_tokens, temperature)`, and `main.py` builds the pipeline `Settings` with `max_completion_tokens` + `extra={"reasoning_effort": "none"}` for gpt-5.x. Never hand-write `max_tokens=` in a completion call. Switching back is `AIVA_LLM_MODEL=gpt-4.1` in `.env`; `LLM_RATES` in utilities.py must know any new model's price or the cost estimate falls back to mini rates.
- **The Bash tool un-escapes `\\n` in heredocs** on this machine — write patch scripts to files (Write tool) instead of inline `python - <<EOF` when the code contains backslash escapes.
- **`run_in_parallel` on the LLM service must stay True** (its default) — sequential mode defeats pipecat's call-grouping and makes her speak once per tool call instead of once per turn.
- **Elevation**: OBS carries a RUNASADMIN compat flag on this machine; it is launched with `__COMPAT_LAYER=RunAsInvoker` (see `launcher.py`) or launch fails with WinError 740.
- **pipecat is pinned at 1.5.0**; most online docs/examples cover the older 0.0.x API and don't match (imports, aggregators, worker/runner model differ). Trust the patterns in `main.py` over external examples.
- **File operations are fenced to the user profile** (`file_operations.resolve_path` rejects anything outside the home directory) — preserve that guardrail.
- Console prints can contain CJK (avatar hotkey names); stdout is reconfigured to UTF-8 with `errors="replace"` so a print can never crash a handler.
