# CLAUDE.md

## What this is

Aiva is a voice AI companion for Windows: a fully streaming voice pipeline (pipecat 1.13.0) with her own Live2D desktop avatar (self-rendered — no VTube Studio), native LLM tool calling, long-term memory, an ambient wake-word mode, and a desktop pixel cat. Everything she says is spoken aloud via TTS — tool results, prompts, and persona text must be short spoken prose (no markdown, emojis, or lists).

Since 2026-09-11 she has a sister, **Saga**, and they live in a **house**: three processes. `aiva/house.py` (always on) owns the one microphone, Deepgram, the wake words, the global hotkeys, the **floor** (who speaks, who overhears, private sister talk) and the conversation log (`aiva/house.db`); each sister is her own process (`main.py --character aiva|saga`) with her own db, state files, space, avatar renderer and voice, connected to the house over loopback TCP (`modules/house_proto.py`). A sister never runs her LLM without a floor grant.

## Versioning

Her version lives in `aiva/version.py` (`__version__`, started at **0.9.0** on 2026-08-28; 1.0.0 = the selfhood/speaker/affect wave validated in real use). It's printed at boot, logged, and shown in the dashboard subtitle. **When you make a notable change, add a bullet under `[Unreleased]` in `CHANGELOG.md`** (Keep a Changelog format); cut a version by moving those bullets into a dated section and bumping `version.py` (SemVer: patch=fix/tune, minor=new capability, major=1.0+). **When the change alters what she is or can do, also add an `Upgrade` to `aiva/modules/upgrades.py`** (stable id, which sisters, when it's really on, one or two sentences of spoken second-person prose): that is how she learns about it, once, on her next boot.

## Commands

- **Python**: 3.11.9 via `.venv` (pyenv-win manages `.python-version`). Always use `.venv\Scripts\python`.
- **Install deps**: `.venv\Scripts\pip install -r requirements.txt`
- **Full production launch**: `start_house.bat` first (the ear + floor; ambient wake-word mode + restart loop), then `start_aiva.bat` and/or `start_saga.bat` (each sister in her own console; either can be stopped and started alone; the launcher starts the house if it isn't up). All three relaunch on exit code 42.
- **Run the house by hand**: `cd aiva && ..\.venv\Scripts\python house.py` (`--list-devices` lists audio devices)
- **Run one sister by hand**: `cd aiva && ..\.venv\Scripts\python main.py --character aiva` (or `saga`); she connects to the house and spawns/adopts her own avatar renderer. Without a house she waits ("waiting for the house") and reconnects.
- **GPT-Live trial (full duplex, a sandbox beside the house)**: stop the house and both sisters, put on headphones, then `cd aiva && ..\.venv\Scripts\python live_trial.py --who aiva --voice marin` (or `--design "a description"`; `--check` validates without a session). Reads her persona + facts read-only and saves nothing.
- **Run with OBS**: `cd aiva && ..\.venv\Scripts\python launcher.py --character aiva` (boots OBS unless `--no-obs`, ensures the house, then imports main)
- **Avatar renderer demo / client probe, cat demo, cat sprites, semi-live task runner check**: the commands and their flags are in `.claude/rules/avatar.md` and `.claude/rules/tasks.md`.
- **ElevenLabs voice helper**: `python tools\pick_voice.py --verify <voice_id>` / `--list --like aiva` / `--play <id>` / `--set <voice_id>` (writes `SAGA_ELEVENLABS_VOICE_ID` into `.env`)
- **Dashboard (never starts a sister)**: `cd aiva && ..\.venv\Scripts\python dashboard.py` (live read-only web view at http://127.0.0.1:8760; the Tasks tab regex-validates ids/job names/session UUIDs before any file lookup; `--once --who saga|conversations|tasks` prints one JSON snapshot, `--open` opens the browser; stdlib-only, safe while they're running; the house launches it). It is read-only except three local-only POSTs: the **Controls** strip (`/api/control`), the **chat box** on the Conversations tab (`/api/say` → the house's `on_say` → `Floor.submit_user_turn`), which types a line to them exactly as if it had been heard — same addressee rules, spoken reply, no voiceprint or vocal affect — and the **Settings** tab's Save (`/api/settings {"updates": {KEY: value|null}}`, also same-Origin only), which validates every value through `modules/settings_registry.py` (secrets masked and never editable) and edits the repo-root `.env` in place (comments/order/line endings kept, atomic, `.env.bak`); config is read at boot, so the reply names what to restart. **A new env knob must be added to `settings_registry.SETTINGS`** — `tests/test_settings_registry.py` greps the code and fails otherwise.
- **Tests** (offline, fast): `.venv\Scripts\python -m pytest tests -q` — covers the task runner and task memory with a scripted fake LLM, fake tools and an in-memory sqlite. No linter configured.

**Do not start, stop, or restart the live house or sister processes yourself** — the user manages their lifecycle. Code changes are picked up when the user restarts them (hot reload is not a thing here). `training/` is a separate offline wake-word training project with its own venv and multi-GB data files; leave it alone unless asked (`hey_saga.yaml` + `gen_samples.py --negatives-for saga` + `trim_features.py hey_saga` is the Saga recipe).

Config lives in `.env` at the repo root and is loaded with `load_dotenv(override=True)` — it beats any same-named variable inherited from the launching shell (a stale `AIVA_LLM_MODEL` in the environment once made a `.env` model change a silent no-op) (API keys, `AIVA_LLM_MODEL`, `AIVA_WAKE_WORD`, device indices/names, the `SAGA_*` block — see README). Runtime event logs go to `aiva/logs/<stem>-YYYYMMDD.log` (`house-`, `aiva-`, `saga-`) via `modules/eventlog.EventLog`; those files are the place to look when diagnosing something that happened hours ago (wake/sleep transitions, wake-word scores, what the house heard, floor grants/releases, announces).

## Architecture

Three processes. The **house** (`aiva/house.py`) is the ear and the floor; each **sister** (`aiva/main.py --character <slug>`) is a mind with a voice:

```
house:   transport.input → MicController → UserAudioTap → Deepgram STT (Flux | nova-3) → ActivityWatcher
         → LLMUserAggregator(stage ctx; flux: Flux's own end-of-turn, no VAD | nova: Silero VAD + smart-turn v3;
                             + FloorUserMuteStrategy)
         → StageRouter → Floor ──(loopback TCP, house_proto)──► the sisters
sister:  HouseLink → OpenAI LLM (native tools) → PrivacyGate → ElevenLabs TTS → BackchannelPlayer → LipSyncTap
         → MindWatcher → UsageTracker → transport.output (audio out only) → assistant aggregator
```

- **Per-area module notes live in `.claude/rules/`** and load only when you open a matching file: `house.md` (house.py, ear, STT, floor, wire, link, sisters, character, kin, speakers, vocal affect, emotion hearing, backchannels), `selfhood.md` (inner, drives, dreams, projects, preferences, capabilities, upgrades), `reading.md` (library, reading, becoming), `tasks.md` (task runner, task memory, terminals), `web-and-limits.md` (web, space, notify, limits, metrics), `avatar.md` (renderer, activity, client, constellation, cat). When you add or change a module, put its notes in the matching file (extend its `paths:` for a new file), not here.
- `aiva/main.py` — one sister's process: her core (`Memory(ch.db_path)` with `store_meta` identity/embedding guards, task memory, reading, becoming, space, preferences, self engine, kin, her own speaker roster), her LLM + tools, her TTS + avatar, the `HouseClient` message handling (`turn` → speaker note + affect + `run_turn`; `overheard` → stored; `interrupt`; `state`; `shutdown` incl. restart), `announce()` → `want_floor`, restart machinery (per-slug marker), session persistence at shutdown. No microphone, no hotkeys.
- `aiva/modules/persona.py` — `PERSONALITY` is now assembled from section constants (byte-identical to before — a golden test pins it) so the shared sections (how you talk, understanding the user, tools, coding, screen, memory, books, web/space, the new SISTER section) are reused by `SAGA_FLOOR`, which has **no authored temperament or tastes**. `named(template, name, …)` fills `{name}`-style slots with `str.replace` (the prompts carry literal JSON braces — never `.format`). `build_system_prompt(..., personality=, name=, tag=, temperament=, forming_note=, sister=)`. Contains the rules for interpreting voice-transcription errors (never quote garbled words back) and the Claude Code delegation workflow (plan first, discuss, execute only on approval). Every other prompt constant (`memory`, `inner`, `becoming`, `reading`, `task_memory`, `tasks`, `computer`) has a `*_T` template and a `name=` kwarg on its store; the module constants still render "Aiva".
- `aiva/modules/memory.py` — SQLite, one file per sister (`aiva/memory.db` for Aiva, `aiva/saga.db`): `messages` (transcripts, flushed every 15 s), `facts` (LLM-extracted at shutdown, injected into the system prompt at boot; `category='sister'` rows are what she learned about her sister and stay out of the LONG-TERM MEMORY block), `facts_superseded` (a fact he said is no longer true moves here with what replaced it, via `replaces` in the extraction reply, so `facts` stays "true now" for every reader), `session_recaps` (generated lazily at the *next* boot so hard kills still get one), `store_meta` (`character` — opening the wrong db aborts boot; `embed_model`/`embed_dim` — a mismatch NULLs every `embedding` column so recall falls back to lexical instead of being silently poisoned). The one connection (loop-thread only) is opened **WAL + synchronous=NORMAL** so the read-only dashboard process never blocks her writes; `close()` runs `wal_checkpoint(TRUNCATE)` so when she's off the file is a plain, current db a `mode=ro` reader can open (read-only WAL access needs a live writer's -shm). `_backup_on_boot()` `VACUUM INTO`s a snapshot under `aiva/backups/` (min 6 h apart so restart-42s don't churn, newest 10 kept) — because her whole *self* (becoming, mood, diary, desires) now lives in this one file, not just chat logs.

## Non-obvious constraints (learned the hard way)

- **Windows audio capture must run at the device's NATIVE sample rate.** Asking for 16 kHz directly yields silence (MME) or corrupted buffers (DirectSound). `MicController` resamples to the 16 kHz that VAD/STT need and re-stamps the StartFrame. Device selection prefers MME host API. The wake-word listener does the same dance independently.
- **Self-hearing gate**: while a sister speaks (+0.5 s cooldown) mic audio is zero-filled *before* STT so nobody transcribes her; `FloorUserMuteStrategy` is the second layer. Both are driven by the **Floor grant** (`gate_active`), not by her audio frames — she plays her voice in another process and a socket round-trip would be too late. Private (text-only) turns never raise the gate, so you can talk during a private sister exchange. Voice barge-in is deliberately disabled — F10 is the interrupt (house → `interrupt` → only the holder injects an `InterruptionFrame`).
- **One grant at a time, and only the house grants.** A sister's LLM runs only on a `turn` from the house (`HouseLink.run_turn`); `announce()` no longer pushes an `LLMRunFrame` — it adds the note and asks for the floor (`want_floor`). `PrivacyGate` fails closed: a response with no latched turn is text-only. Keep it that way; it is what makes "they never talk over each other" true. The one exception that isn't one: `prepare` (answer sooner, `AIVA_SPECULATE`) runs her LLM ahead of a turn, but pipecat's speculation gate inside her LLM service holds the reply, so nothing reaches `PrivacyGate`, her voice or the house until a granted `turn` releases it (`.claude/rules/house.md`).
- **Overheard lines are role `user`** (`[He said to Saga: "…"]`, `[Saga said to him/you: "…"]`) so they are persisted by `save_new_messages` and trimmed by `trim_context`; the fact-extraction prompt knows they were spoken by her sister, never by you. Ephemeral stage cues are `system` and removed by identity after the reply.
- **Global hotkeys live in the house only** — the `keyboard` library is process-global; two registrants would both fire.
- **The avatar renderer outlives sister restarts, so renderer changes need a protocol bump**: a sister adopts the running body; `AvatarClient.ensure_running` retires a renderer whose `hello.version` < `avatar_ipc.PROTOCOL_VERSION` (quit, then spawn; placement carried in the state file). Bump `PROTOCOL_VERSION` whenever the renderer gains a command or a visible behaviour, or the live body never gets the change.
- **Activity props live in the GL frame, not in their own windows**: the old `PropWindow` (a separate top-level window at fixed monitor fractions) was mis-sized, wrong for Saga and could fall behind her. The ariu mesh has two root-level drawables (`ArtMesh211/212`, no parent part, so part opacity can't hide them) that sit behind her shirt, which is why the book is painted OVER the hold pose rather than between body and fingers via a second hands-only pass. Verify pose/prop changes offscreen (QOffscreenSurface + FBO + `glViewport`, or the real `AvatarWindow` with `WA_DontShowOnScreen` + `grabFramebuffer()`), never by starting her.
- **Per-instance avatar renderer**: `avatar_ipc.state_path(instance)` (`avatar_state.json` for Aiva, `saga_avatar_state.json` for Saga); the single-instance guard is per state file; `AvatarClient(instance, model)` refuses to adopt a renderer whose `hello.model` differs. `MODEL_FIXUPS` is keyed by model basename — `saga` has its own `camo_skin` (her textures are pinker); a blind alias leaves an Aiva-coloured patch under her lips.
- **Two output streams on one device**: both sisters play through the same speaker device; MME shared mode mixes them (WASAPI exclusive would refuse the second open) — keep the MME preference in `ear.device_index`.
- **Saga forms herself**: `Character.baseline_traits=()` and `baseline_tastes=False`; the self-loop digest may propose `temperament` traits (adopt 0.35, rendered only once reinforced past 0.5, cap 8, half-life 180 d, contradiction = erosion not veto). Don't hand her authored bullets — that was the user's explicit decision.
- **Aiva forms too, but only upward**: since 2026-09-13 an authored character also gets a temperament key in her diary (`TEMPERAMENT_CLAUSE_ON_TOP`, "most days have none") and renders it as **WHAT LIVING HAS ADDED TO YOU**, on top of `PERSONALITY` rather than instead of it. The asymmetry is the point: `adopt_temperament` passes her authored baseline as `floor_vecs`, and a negation that lands there is *dropped* (logged `temperament blocked`), never eroded — she can unlearn what she learned, not what she was written to be. A self-forming sister passes no floor, so her own core is the only thing a negation can erode.
- **Ambient mode economics**: while asleep, `MicController` *drops* audio frames entirely so Deepgram receives (and bills) nothing. Pipecat's built-in worker idle timeout must stay `None` — with frames dropped, its default 300 s monitor would silently kill her.
- **Wake word is two-stage**: the custom `hey_aiva.onnx` model fires on TV/game speech with the same scores (up to 0.96) as real wakes, so a wake-word hit is only a *candidate*. `WakeWordListener` passes a 2.5 s pre-roll; `MicController` injects it ahead of live audio and holds the wake as provisional (`verifying`, `visibly_awake` False — eyes stay shut); `ActivityWatcher` confirms on the first final transcript containing her name (`mentions_name`) or rejects and puts her back to sleep, dropping the transcript before the LLM. Don't "simplify" this back to trusting the model score — see the `wake rejected` lines in the logs for what it filters.
- **Restart machinery**: `restart_self`/Ctrl+Alt+R exit with code 42; `start_aiva.bat` relaunches (or a detached watcher process does if she wasn't started via the bat). `.restart_marker` tells the next boot to say "I'm back" instead of a full intro. The avatar renderer stays up across restarts — the new process adopts it via `aiva/avatar_state.json`; only a real quit kills it.
- **Lip-sync timing**: TTS audio frames pass `LipSyncTap` FASTER than real-time (the output transport paces playback). RMS chunks are queued in the renderer with durations and consumed at wall-clock rate from `BotStartedSpeakingFrame`. Flush only on `InterruptionFrame` — flushing on `TTSStoppedFrame` (end of *generation*) would close her mouth mid-sentence every turn.
- **PyQt5, not PyQt6/PySide6**: the renderer's transparent window depends on it — Qt6 bindings have a known black-background bug with `WA_TranslucentBackground` + OpenGL (live2d-py issue #98).
- **Shell command safety is non-bypassable**: `run_command` only *stages* a command; execution requires the user's verbal confirmation followed by `confirm_pending_command`. Keep this two-step gate intact. The task runner obeys the same rule from the other side: a `shell` step pauses the task (`awaiting_user`, kind `confirm_command`) until `answer_task` brings a yes, and only then calls `tools.execute_shell` — the single place a command a model wrote actually runs. The runner's own fixed commands are the only exception and are never model-composed: `run_git` for worktree snapshots and the `repo_status` look tool, and `run_test_command` for the project's own pytest (user decision 2026-10-13; the `run_tests` look tool may only add test-file paths that `pick_test_targets` finds inside the project — never options). Looking needs no shell at all: the task agent's `LOOK_TOOLS` (`read_file`, `find_files`, `search_text`, `repo_status`, `run_tests`) are home-fenced and read-only, so the planner/agent prompts keep the shell for changes (2026-10-14: nine approvals for one verification). Writing a file is `create_file`, which never replaces an existing one unless `overwrite` is true (a taken name gets " (2)"), so the agent is told it's already approved; an agent that calls `step_failed` before trying any tool is sent back once (`pushed_back`). `search_text` skips `BINARY_EXTS` unopened (a repo search once read 1 GB of training audio). A task's question is answered only on a turn HE spoke in: `make_task_handlers(heard_him=)` (main.py: `link.current_turn.kind in user|both_second`) — she once said yes to nine of her own commands on her news turns. `run_command`/`confirm_pending_command`/`claude_code` are deliberately NOT in `RUNNER_TOOL_ALLOW`.
- **Reading is greenfield and cost-bounded**: study/synthesis run on `AIVA_STUDY_MODEL`/`AIVA_STUDY_SYNTH_MODEL` (default luna/terra — their OWN tokens-per-minute bucket, never the voice model); per-session and per-book (`AIVA_BOOK_MAX_COST_USD`=3) caps; a novel costs ~10-25 cents. `library.py` imports no sqlite (parse in a thread, write on the loop); `commit_section` is the ONLY place the book cursor moves, atomically with the note; quotes are verified verbatim ≤25 words and never enter the prompt. Books resume from a persisted cursor (they are NOT runner tasks); `book_memory.reconcile_stale()` only marks the in-flight session interrupted.
- **Reading changes her within bounds**: the static `PERSONALITY` traits are the floor; a book may deepen or add a facet, never contradict it (compatibility gate) — traits cap at 12, fade if unused, and a voice `drop_trait` removes one forever. Tell-once is announced-at-injection (rides the book-finish note); the four persona blocks all carry the anti-recite rule so she never lectures or quotes unprompted. Curiosity thresholds live in `becoming.CURIOSITY` and are tunable from the `becoming:`/`read:` log lines; `_user_present` uses Win32 GetLastInputInfo so she only asks to read when you're at the PC but quiet.
- **Task autonomy is experience-based by design** (user decision 2026-08-25): done-this-kind-of-thing-before → just do it with a one-line heads-up; novel, previously corrected, irreversible, shell or delegate → confirm first; options only when the planner flags genuinely different approaches. The voice LLM may be MORE careful than `decide_autonomy` says, never less. Don't re-tune the thresholds without checking `familiarity:` lines in the logs.
- **`answer_task` must find the task already waiting**: `TaskRunner._prepare_wait` puts a task into `awaiting_user` BEFORE `start_task` returns its in-turn question, because the user's yes can arrive in the same voice turn. Don't reorder that.
- **OpenAI tokens-per-minute is the scarce resource** (org is on the 30k TPM tier for gpt-4.1 as of 2026-08-26). Each voice turn re-sends the whole context + ~5.5k tokens of tool schemas + ~3.8k of system prompt. Keep side-calls OFF the voice model: `AIVA_TASK_MODEL` and `AIVA_VISION_MODEL` default to gpt-4.1-mini in `.env` (own bucket); `PatientOpenAILLMService`/`AIVA_LLM_MAX_RETRIES` make 429s a backoff instead of a dead turn; `trim_context()` (every 15 s in `flush_transcripts`, budget `AIVA_CONTEXT_BUDGET_CHARS`=24000) keeps history bounded — it saves transcripts first and calls `memory.forget_saved()` so persistence stays consistent, and never drops in-flight tool exchanges. Don't add per-turn LLM calls on the voice model without checking this.
- **Models are gpt-5.6-luna everywhere by default (voice, tasks, vision) since 2026-08-26** — 500k TPM at tier 1, ~$0.20/$1.20 per 1M, sub-second first token. The gpt-5.x line has a different Chat Completions shape: `max_tokens` is rejected (use `max_completion_tokens`) and function tools REQUIRE `reasoning_effort: "none"` (default effort → 400). Every direct OpenAI call goes through `utilities.llm_kwargs(model, max_tokens, temperature)`, and `main.py` builds the pipeline `Settings` with `max_completion_tokens` + `extra={"reasoning_effort": "none"}` for gpt-5.x. Never hand-write `max_tokens=` in a completion call. **gpt-6-luna is on the same shape** (`utilities.gpt5_shape`, verified live 2026-10-23: the old shape is a 400 on `max_tokens`); gpt-6.1-sol is deliberately not matched (it rejects effort `none`). Each sister's voice model is `Character.llm_model`: `AIVA_LLM_MODEL`, which Saga shares unless `SAGA_LLM_MODEL` is set (on the voice-upgrades branch Aiva runs gpt-6-luna and Saga stays on gpt-5.6-luna to compare). gpt-4.1 / gpt-4.1-mini shut down 2027-01-14, so they are no fallback any more; code defaults are gpt-5.6-luna. `LLM_RATES` in utilities.py must know any new model's price or the cost estimate falls back to mini rates.
- **The Bash tool un-escapes `\\n` in heredocs** on this machine — write patch scripts to files (Write tool) instead of inline `python - <<EOF` when the code contains backslash escapes.
- **`run_in_parallel` on the LLM service must stay True** (its default) — sequential mode defeats pipecat's call-grouping and makes her speak once per tool call instead of once per turn.
- **Elevation**: OBS carries a RUNASADMIN compat flag on this machine; it is launched with `__COMPAT_LAYER=RunAsInvoker` (see `launcher.py`) or launch fails with WinError 740.
- **pipecat is pinned at 1.13.0** (main is still on 1.5.0); most online docs/examples cover the older 0.0.x API and don't match (imports, aggregators, worker/runner model differ). Trust the patterns in `main.py` over external examples.
- **File operations are fenced to the user profile** (`file_operations.resolve_path` rejects anything outside the home directory) — preserve that guardrail.
- Console prints can contain CJK (avatar hotkey names); stdout is reconfigured to UTF-8 with `errors="replace"` so a print can never crash a handler.
