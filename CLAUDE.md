# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Aiva is a voice AI companion for Windows: a fully streaming voice pipeline (pipecat 1.5.0) with her own Live2D desktop avatar (self-rendered — no VTube Studio), native LLM tool calling, long-term memory, an ambient wake-word mode, and a desktop pixel cat. Everything she says is spoken aloud via TTS — tool results, prompts, and persona text must be short spoken prose (no markdown, emojis, or lists).

Since 2026-09-11 she has a sister, **Saga**, and they live in a **house**: three processes. `aiva/house.py` (always on) owns the one microphone, Deepgram, the wake words, the global hotkeys, the **floor** (who speaks, who overhears, private sister talk) and the conversation log (`aiva/house.db`); each sister is her own process (`main.py --character aiva|saga`) with her own db, state files, space, avatar renderer and voice, connected to the house over loopback TCP (`modules/house_proto.py`). A sister never runs her LLM without a floor grant.

## Versioning

Her version lives in `aiva/version.py` (`__version__`, started at **0.9.0** on 2026-08-28; 1.0.0 = the selfhood/speaker/affect wave validated in real use). It's printed at boot, logged, and shown in the dashboard subtitle. **When you make a notable change, add a bullet under `[Unreleased]` in `CHANGELOG.md`** (Keep a Changelog format); cut a version by moving those bullets into a dated section and bumping `version.py` (SemVer: patch=fix/tune, minor=new capability, major=1.0+). **When the change alters what she is or can do, also add an `Upgrade` to `aiva/modules/upgrades.py`** (stable id, which sisters, when it's really on, one or two sentences of spoken second-person prose): that is how she learns about it, once, on her next boot.

**Do not start, stop, or restart the live house or sister processes yourself** — the user manages their lifecycle. Code changes are picked up when the user restarts them (hot reload is not a thing here). `training/` is a separate offline wake-word training project with its own venv and multi-GB data files; leave it alone unless asked (`hey_saga.yaml` + `gen_samples.py --negatives-for saga` + `trim_features.py hey_saga` is the Saga recipe).

Config lives in `.env` at the repo root and is loaded with `load_dotenv(override=True)` — it beats any same-named variable inherited from the launching shell (a stale `AIVA_LLM_MODEL` in the environment once made a `.env` model change a silent no-op) (API keys, `AIVA_LLM_MODEL`, `AIVA_WAKE_WORD`, device indices/names, the `SAGA_*` block — see README). Runtime event logs go to `aiva/logs/<stem>-YYYYMMDD.log` (`house-`, `aiva-`, `saga-`) via `modules/eventlog.EventLog`; those files are the place to look when diagnosing something that happened hours ago (wake/sleep transitions, wake-word scores, what the house heard, floor grants/releases, announces).

## Architecture

Three processes. The **house** (`aiva/house.py`) is the ear and the floor; each **sister** (`aiva/main.py --character <slug>`) is a mind with a voice:

```
house:   transport.input → MicController → UserAudioTap → Deepgram STT (Flux | nova-3) → ActivityWatcher
         → LLMUserAggregator(stage ctx; flux: Flux's own end-of-turn, no VAD | nova: Silero VAD + smart-turn v3;
                             + FloorUserMuteStrategy)
         → StageRouter → Floor ──(loopback TCP, house_proto)──► the sisters
sister:  HouseLink → OpenAI LLM (native tools) → PrivacyGate → ElevenLabs TTS → BackchannelPlayer → LipSyncTap
         → MindWatcher → UsageTracker → transport.output (audio out only) → assistant aggregator
```

- `aiva/house.py` — the house entry: mic input only, `MicController` (F9 mute = full **deafen**: zero-fills the STT path AND makes `wake()` ignore any wake with a preroll/verify, so the wake word can't wake it while muted — a sister's own preroll-less announces still can), two-stage wake word (N models via `modules/wake.py`, a verified transcript must contain a sister's name), idle/sleep, global hotkeys (F10 interrupt → holder only; `AIVA_HOTKEY_SISTER_TALK` flips private/audible; Ctrl+Alt+R restarts the sisters; Ctrl+Alt+X quits all), the speaker voiceprint + vocal affect computed ONCE per turn and forwarded, the emotion-hearing side-call started per turn in the background (never awaited before the grant; a late reading goes out via `Floor.late_affect` → queued turn or `proto.Affect`), the arbiter side-call, the dashboard launch, `aiva/house.db` (`house_transcript`, `house_events`, `house_kv`, the shared spend caps, house metrics) and `aiva/house_state.json` `{port, pid, boot_id}`.
- `aiva/modules/ear.py` — `MicController` / `ActivityWatcher` / `UserAudioTap` + device helpers, moved out of main.py. The mic gate is raised by the **Floor grant** (`set_speaking`), not by a Bot*SpeakingFrame — the speaking sister is in another process, and gating at grant is strictly earlier than any audio.
- `aiva/modules/house_stt.py` — `AIVA_STT=flux|nova` (default flux): `STTConfig.from_env` (pure; `AIVA_FLUX_EOT_THRESHOLD`/`_EOT_TIMEOUT_MS`/`_IDLE_CLOSE_S`), `build_stt`, `stage_params`. Flux (`flux-general-en`, 16 kHz, eager EOT OFF) drives the stage turn via `ExternalUserTurnStrategies` (no Silero, no smart-turn) and emits ONE final transcript per turn at EndOfTurn (no interims; `on_update` pokes the idle timer). Flux has no free keepalive, so `HouseFluxSTTService` closes its socket after the idle-close seconds without audio (ambient sleep drops audio) and reopens on the next frame — the wake pre-roll waits in the STT queue for the handshake. Empty finals are dropped by `ActivityWatcher` so a noise-only turn can't reject a wake.
- `aiva/modules/backchannel.py` — "mhm" while he talks. House: `Backchanneler` reads Flux's TurnInfo stream (`HouseFluxSTTService.on_turn_info`); a pause is the partial transcript not growing for `pause_s` while Flux holds the turn open; pure `decide()` gates it (min speech, cooldown, eot ceiling just under the end-of-turn threshold, no finished question, no dangling word/filler, probability), the house adds asleep/muted/unverified/floor-busy, and `target()` picks ONE sister. `proto.Backchannel(clip, voice)` is NOT a floor grant. The clip is deliberately not mic-gated (it would cut his words); `strip_echo()`/`strip_final` removes its echo from his final transcript at the word index where it fired. Sister: `ClipCache` synthesises `PHRASES` once per voice id + TTS model into `aiva/voice_cache/<slug>/` in the background; `house_link.BackchannelPlayer` (after the TTS) pushes `TTSStarted(append_to_context=False)`/audio/`TTSStopped`, `HouseLink.expect_backchannel()` swallows its speaking frames so the house never sees a turn, and `BackchannelVoice` adds the avatar `nod` cue (renderer protocol 8). Tests: `tests/test_backchannel.py`.
- `aiva/modules/house_stage.py` — `StageRouter` (consumes the stage aggregator's `LLMContextFrame`, hands the user's text to the Floor, drops mic audio) and `FloorUserMuteStrategy` (aggregator-level twin of the zero-fill, reads `floor.gate_active`).
- `aiva/modules/sisters.py` — PURE decisions: `NameSet`s (Aiva/Saga spellings + loose regexes), `addressee_decision` (names / group words / wake hint / follow-up / sticky / else arbiter), `exchange_should_continue` (sister rounds; caps, backoff, per-hour, quiet hours), `floor_decision` (priority `user > both_second > announce > sister > initiative`), `Turn`, the overheard-line and cue builders, `ARBITER_PROMPT` + tolerant `parse_arbiter_reply`. `ExchangeConfig.from_env()` reads the `AIVA_SISTER_*` caps.
- `aiva/modules/house_floor.py` — the `Floor`: the single grant authority. Queue → grant (holder, `gate_active` for audible turns, `turn` message) → `response start` ack → tools ±1 (re-run) → `response end` → release on `speaking off` | 1.5 s grace | immediately for private turns | 120 s cap | client death (+3 s gate tail) | interrupt. `said` → `house_transcript` row + `overheard` to the other sister + maybe a `sister` continuation (text-only in private mode). Presence: absent addressee → the present sister gets an `absent_cue`. Daily cap on sister-initiated chats. **His errands run to the end** (2026-10-14, he'd been playing middle man): "ask/tell/check with her" (`errand_to`) puts `errand_cue` on the turn (ask her NOW, opening with her name); a line routed away from an absent sister is kept in `_waiting` and picked up by the stand-in with `arrival_cue` when she joins within `ERRAND_TTL_S`; when an exchange rooted in an errand (`wants_report`) ends, the sent sister gets one `report` turn (`report_cue`, never continues). A call is a sentence opening with her name plus a comma/dash, a greeting or a question (`vocative`/`called_in`) — "Saga's already here" is about her, not to her. Knows nothing about sockets or pipecat; every timer is driven from `tick()`.
- `aiva/modules/house_proto.py` — the wire protocol (dataclasses + `encode/decode`, newline JSON): character→house `hello, response, tool, speaking, said, event, want_floor, mode, sleep, wake, pong, bye` (plus `control` and `say` from a `role=control` client, never a sister); house→character `welcome, reject, turn, overheard, affect, backchannel, interrupt, mode, state, absent, ping, shutdown`. Only `hello→welcome` is request/response; `turn` is the ONLY message that runs a sister's LLM.
- `aiva/modules/house_server.py` / `house_client.py` — `HouseServer` (one `ClientSession` per sister, sync `send` for the Floor, dup-slug ping-then-reject/replace, ping/pong liveness, `event` relay with `actor`/`event_id`, `state` broadcasts) and `HouseClient` (discover via the state file, `hello`, reader loop, 0.5→5 s backoff "waiting for the house", ≤5 queued `want_floor`s).
- `aiva/modules/house_link.py` — the sister-side processors: `HouseLink` (`run_turn` adds the lines to her context and pushes `LLMContextFrame` — no user aggregator/VAD/transcripts in her process; `add_overheard`; `interrupt` injects `InterruptionFrame` from below), `PrivacyGate` (stamps `skip_tts` on the LLM frames of a non-audible turn so the TTS forwards them untouched while the assistant aggregator still commits the text; fails closed; it is ALSO where a turn ends — straight after the LLM the frames are in true order, so a response that called a tool waits for the re-run and the first one without a tool sends `said` with the whole turn's text. Don't move that back to the assistant aggregator: after the ElevenLabs TTS the end frames are delayed or dropped and replies after a tool get lost), `MindWatcher` (`response start/end`, `tool ±1`), `UsageTracker` (+ `record("tts")`), `LipSyncTap`.
- `aiva/modules/character.py` — `Character.from_env(slug)`: everything that makes a sister herself (name, spellings, db/state paths, persona floor, voice, voice model (`llm_model`), avatar model, space dir, mood baseline, speaker seeding, wake model). Aiva's values reproduce the pre-house defaults byte-for-byte; Saga's come from the `SAGA_*` env block.
- `aiva/modules/kin.py` — what a sister knows about her sister **from experience**: `kin_observations` (did/made/read/said/likes, rolled up, strength-weighted, fading, vetoable) fed by the house-relayed public `event`s (tool use via `tools.bind_tool_hook`, autonomous acts, space finds, reading, tasks) and by her own diary digest (`sister_notes`); renders the "YOUR SISTER" block and answers `recall_about_sister` with **no LLM call** ("I haven't seen her do that" when unknown). Catch-up from `house_events` by a per-character cursor.
- `aiva/main.py` — one sister's process: her core (`Memory(ch.db_path)` with `store_meta` identity/embedding guards, task memory, reading, becoming, space, preferences, self engine, kin, her own speaker roster), her LLM + tools, her TTS + avatar, the `HouseClient` message handling (`turn` → speaker note + affect + `run_turn`; `overheard` → stored; `interrupt`; `state`; `shutdown` incl. restart), `announce()` → `want_floor`, restart machinery (per-slug marker), session persistence at shutdown. No microphone, no hotkeys.
- `aiva/modules/library.py` — pure, sqlite-free, thread-safe book readers: EPUB (stdlib zip+XML+html.parser), TXT/MD (decode chain + Project Gutenberg strip), PDF (pypdf; scan detection, running-header removal, de-hyphenation, outline→chapters). `parse_file` → ordered `Section`s; `segment`/`normalize_sections`/`chunk`. Runs under `asyncio.to_thread`; `clean_text` normalises whitespace ONLY so copied quotes verify verbatim.
- `aiva/modules/reading.py` — `BookMemory` (7 tables on `Memory.conn`) + `ReadingEngine`. One background reading *session* at a time (`llm.create_task`): per section a close-reading note (summary/key ideas/exact ≤25-word quotes VERIFIED against the text/nuances/reflection/running summary+state), `commit_section` moves the cursor atomically with the note (kill mid-section → redo that section, never a dup), session wrap → "what struck me", whole-book synthesis on finish (own model), embedding `recall`. Announces via injected callbacks (quiet while asleep). Hooks `on_section/on_session_end/on_book_finished/on_book_added` feed becoming.
- `aiva/modules/becoming.py` — how reading changes her: `reading_lessons`, `traits`, `voice_notes`, `becoming_state` on `Memory.conn`. On book finish, one JSON call extracts candidates; `validate_candidates` (pure) enforces first-person, evidence-in-notes, bounded content, and baseline-contradiction rejection; `adopt` caps trait strength 0.7 / 12 active, dedupes+reinforces, `fade`s unused ones; tell-once rides the finish note; `drop_trait` vetoes permanently; `reading_permission` + the pure `curiosity_decision` govern when she asks to read. `prompt_blocks` renders the four persona blocks. `python -m modules.becoming --show` audits her.
- `aiva/modules/inner.py` — her **nervous system** (substrate for the selfhood work, `docs/PLAN-selfhood-and-eval.md`). Phases 1–2 built & offline (**NOT yet wired into `main.py`** — no live effect until then): `InnerState` (valence/arousal/social/focus dials, persisted to `aiva/inner_state.json`, decays toward an env-set baseline like the cat), `InnerBrain` (PURE: `decay`/`integrate` with a salience-gate + material-change flag, `now` always injected), `ExperienceBus` (`experience` table on `Memory.conn`; `emit`/`drain`/`mark_consumed` — the shared bloodstream that replaces point-to-point hooks), and `SelfEngine` (`journal` + `desires` tables; `tick` drains the bus → moves mood → when earned writes a private diary entry via `JOURNAL_PROMPT` on the side model + forms desires deduped/vetoable like traits; `should_journal`, `add_desire`/`drop_desire`/`recall_journal`). Journal is her inner voice, NEVER announced. The dashboard reads all of it (mood dials, experience stream, diary, wishes). **Wired live in `main.py` (Phases 2–3 core):** the self loop `self_watch` ticks every `AIVA_SELF_TICK_S`; reading emits `chapter_read`/`book_finished` (mood-hinted by the note's feeling) and time emits `daypart`; mood + open wishes render as the HOW YOU FEEL / WHAT YOU FIND YOURSELF WANTING persona blocks (refreshed on material mood change via `refresh_system_prompt`); voice tools `note_desire`/`drop_desire`/`recall_journal`/`set_initiative`; a private diary entry is forced at shutdown (digesting recent conversation). **Phase 4 (initiative) shipped:** the pure `initiative_decision` (mood + presence + backoffs/caps/quiet-hours/boot-grace) drives `initiative_tick` in `self_watch` so she can `express` a feeling or `ask` about an open wish on her own. **Phase 5 (autonomous action) shipped:** `initiative_decision` now also returns `"act"`, and `initiative_tick`→`_do_act` pursues a wish herself via an injected `_act(desire)` dispatcher — but ONLY when the injected `actionable(desire)` predicate approves it (auto-tier via `capabilities.match`, not paused; wired in `main.py` as `_self_actionable`→`_act_on_wish`, v1 = find-and-keep an image to her space, gated by `AIVA_SELF_ACT` + a tighter `max_acts_per_day` + the `ServiceLimits` Tavily cap). The wish is consumed (`status='acted'`) and a `self_act` event is emitted (learn-by-doing) BEFORE dispatch. Anything that spends/sends/touches his files/edits her code stays an `ask`. `set_initiative(always|ask|quiet|never)` is the switch, tracked in a `self_kv` table. **Emitters MUST run on the event-loop thread** (sqlite conn rule) — so the cat's autonomous changes (tk thread), per-turn conversation sentiment, and avatar-expression-from-mood are the Phase-3/4 tail. `python -m modules.inner --show` audits her. Tests: `tests/test_inner.py`, `tests/test_self_engine.py`, `tests/test_initiative.py`, `tests/test_persona.py`.
- `aiva/modules/drives.py` — **v3's engine** (`docs/PLAN-v3.md`), PURE and clock-injected: four **needs** (connection/novelty/competence/rest, 0 starved..1 met) that `deplete` with time (rest refills while the house sleeps; downtime counts as ≤12 h), are refilled/spent by event kinds via `EFFECTS` (`satisfy`, diminishing returns), lean on her mood (`pressure`), and `tension` when two press at once; `rhythm_update`/`expectation_event` (P(he's around) per weekday-hour → `expected_absent`/`unexpected_presence`); `reunion`/`is_friction`/`repair_note`; `initiative_outcome` (welcomed/ignored). `SelfEngine` owns the I/O: needs live in `InnerState.needs`/`needs_ts`, `_drive_step`/`_rhythm_step`/`_initiative_feedback` run in `tick`, and **`heard(text, affect)`** — called by `main.py` for every user turn BEFORE her reply — emits the `conversation` event and returns that turn's reunion/repair notes. `initiative_decision` reads the needs (missing him → sooner, restless → act sooner, worn → wider gap). Diary wishes must point outward (`desire_is_outward`, the 2026-10-12 introspection rut). A `focus` expires after 24 h (`focus_ts`). Toggle `AIVA_DRIVES`. Tests: `tests/test_drives.py`.
- `aiva/modules/dreams.py` — **her nights** (`Consolidation`, side model, label `dream`): `maybe_run(asleep)` from `self_watch` → once a day after `AIVA_DREAM_HOUR` while quiet, `dream()` replays the last ~26 h of `messages` + feedback events into `moments` (landed/flat + `better`) and 0-2 **habits** ("When X, I Y"; `valid_habit` rejects people-pleasing and inner-weather ones; adopt 0.35, reinforce, weaken, half-life 21 d, cap 8, vetoable), then `forget()` deletes consumed experience older than 30 d under salience 0.3. `rewrite_story()` revises a ≤180-word autobiography about every `AIVA_STORY_DAYS`. `prompt_data()` → the YOUR STORY SO FAR / HABITS YOU'VE FORMED / MOMENTS THAT LANDED blocks. `--export` writes chat JSONL for a future open-weight LoRA. Her gpt-5.x model can't be fine-tuned, and OpenAI is winding fine-tuning down, so she changes in context. `--show [--who saga]` audits. Toggle `AIVA_DREAMS`.
- `aiva/modules/projects.py` — **her projects**: `ProjectBook.promote(open desires)` turns a strong (≥0.75), pursuable wish (`project_kind`: collection | learn; nothing with him/buy/send/code in it) into a project (desire status `project`, ≤3 active); `main._project_tick` does one step when `step_due` (restless or wanting to be useful, idle ≥10 min, ≤3/day, ≥6 h gap, Tavily allowed, not quiet hours): a collection keeps an image in her space (`save_find(match_meaning=False)`, subject from `describe_image`), a learn project keeps search snippets in its notes; `project_done` is announced. Voice tool `let_go(kind=habit|project)`. Toggle `AIVA_PROJECTS`. Tests: `tests/test_dreams.py`.
- `aiva/modules/preferences.py` — her **mutable likes/dislikes/opinions**, distinct from `becoming` (which is reading-only and forbidden from contradicting the baseline). `Preferences` store (one `preferences` table + a `pref_kv` on `Memory.conn`) with SIGNED `valence` (magnitude=conviction, sign=like/agree vs dislike/disagree), `kind` taste|opinion, `origin` baseline|reading|conversation|reflection, deduped by subject embedding (cosine 0.86 / jaccard 0.60 fallback), capped (`MAX_ACTIVE`=24, `ADOPT_CAP`=0.6 so one event can't create a strong pref), faded (half-life 120d / 240d baseline, floor 0.2, every ~20h) and permanently vetoable (`drop`). The coherence guard is **inertia, not a veto**: the PURE `evolve(valence, evidence, origin, direction)` reinforces toward the extreme on same-direction evidence and *erodes toward 0 first* on opposite evidence — flipping only after sustained counter-experience, and ~2× slower for `origin='baseline'`. `seed_from_baseline()` (run once at boot) seeds her frozen tastes as `baseline`-origin rows; from then on they evolve like any other. `apply()` is async (embeds), returns inserted|reinforced|eroded|flipped|blocked|rejected; `_BOUNDED` rejects harmful content. Formation piggybacks `SelfEngine._digest` (the `preferences` key in `JOURNAL_PROMPT` — NO extra LLM call); `SelfEngine(preferences=…)` applies each delta. Rendered as the "WHERE YOU STAND" persona block (`prompt_block` → likes/dislikes/opinions, refreshed on change); voice tools `note_preference`/`drop_preference`. The PERSONALITY split moved *tastes* here and left *temperament/voice* frozen, so `persona.baseline_traits()` (becoming's anti-contradiction gate) now protects character only. `python -m modules.preferences --show` audits. Tests: `tests/test_preferences.py` (+ formation in `tests/test_self_engine.py`, split in `tests/test_persona.py`).
- `aiva/modules/web.py` — her **reach to the internet** (provider-agnostic, dependency-injected so it's fully offline-testable). `WebConfig.from_env()` + `WebClient(cfg, get=, post=)`: `search(query, kind=info|images|videos)` (Tavily `/search`, `include_images` for images), `extract(url)` (Tavily `/extract`, else `requests`+stdlib HTML strip), and the security-critical `download(url, dest_dir)` — content-type allow-list (image/ text/ pdf/ mp4 only), size cap (`AIVA_WEB_MAX_MB`), timeout, filename **extension derived from the content-type not the URL** (an executable can never be written), sha256, never executed. ## Non-obvious constraints (learned the hard way)

- **Windows audio capture must run at the device's NATIVE sample rate.** Asking for 16 kHz directly yields silence (MME) or corrupted buffers (DirectSound). `MicController` resamples to the 16 kHz that VAD/STT need and re-stamps the StartFrame. Device selection prefers MME host API. The wake-word listener does the same dance independently.
- **Self-hearing gate**: while a sister speaks (+0.5 s cooldown) mic audio is zero-filled *before* STT so nobody transcribes her; `FloorUserMuteStrategy` is the second layer. Both are driven by the **Floor grant** (`gate_active`), not by her audio frames — she plays her voice in another process and a socket round-trip would be too late. Private (text-only) turns never raise the gate, so you can talk during a private sister exchange. Voice barge-in is deliberately disabled — F10 is the interrupt (house → `interrupt` → only the holder injects an `InterruptionFrame`).
- **One grant at a time, and only the house grants.** A sister's LLM runs only on a `turn` from the house (`HouseLink.run_turn`); `announce()` no longer pushes an `LLMRunFrame` — it adds the note and asks for the floor (`want_floor`). `PrivacyGate` fails closed: a response with no latched turn is text-only. Keep it that way; it is what makes "they never talk over each other" true.
- **Overheard lines are role `user`** (`[He said to Saga: "…"]`, `[Saga said to him/you: "…"]`) so they are persisted by `save_new_messages` and trimmed by `trim_context`; the fact-extraction prompt knows they were spoken by her sister, never by you. Ephemeral stage cues are `system` and removed by identity after the reply.
- **Global hotkeys live in the house only** — the `keyboard` library is process-global; two registrants would both fire.
- **The avatar renderer outlives sister restarts, so renderer changes need a protocol bump**: a sister adopts the running body; `AvatarClient.ensure_running` retires a renderer whose `hello.version` < `avatar_ipc.PROTOCOL_VERSION` (quit, then spawn; placement carried in the state file). Bump `PROTOCOL_VERSION` whenever the renderer gains a command or a visible behaviour, or the live body never gets the change.
- **Activity props live in the GL frame, not in their own windows**: the old `PropWindow` (a separate top-level window at fixed monitor fractions) was mis-sized, wrong for Saga and could fall behind her. The ariu mesh has two root-level drawables (`ArtMesh211/212`, no parent part, so part opacity can't hide them) that sit behind her shirt, which is why the book is painted OVER the hold pose rather than between body and fingers via a second hands-only pass. Verify pose/prop changes offscreen (QOffscreenSurface + FBO + `glViewport`, or the real `AvatarWindow` with `WA_DontShowOnScreen` + `grabFramebuffer()`), never by starting her.
- **Per-instance avatar renderer**: `avatar_ipc.state_path(instance)` (`avatar_state.json` for Aiva, `saga_avatar_state.json` for Saga); the single-instance guard is per state file; `AvatarClient(instance, model)` refuses to adopt a renderer whose `hello.model` differs. `MODEL_FIXUPS` is keyed by model basename — `saga` has its own `camo_skin` (her textures are pinker); a blind alias leaves an Aiva-coloured patch under her lips.
- **Two output streams on one device**: both sisters play through the same speaker device; MME shared mode mixes them (WASAPI exclusive would refuse the second open) — keep the MME preference in `ear.device_index`.
- **Saga forms herself**: `Character.baseline_traits=()` and `baseline_tastes=False`; the self-loop digest may propose `temperament` traits (adopt 0.35, rendered only once reinforced past 0.5, cap 8, half-life 180 d, contradiction = erosion not veto). Don't hand her authored bullets — that was the user's explicit decision.
- **Aiva forms too, but only upward**: since 2026-09-13 an authored character also gets a temperament key in her diary (`TEMPERAMENT_CLAUSE_ON_TOP`, "most days have none") and renders it as **WHAT LIVING HAS ADDED TO YOU**, on top of `PERSONALITY` rather than instead of it. The asymmetry is the point: `adopt_temperament` passes her authored baseline as `floor_vecs`, and a negation that lands there is *dropped* (logged `temperament blocked`), never eroded — she can unlearn what she learned, not what she was written to be. A self-forming sister passes no floor, so her own core is the only thing a negation can erode.
- **Ambient mode economics**: while asleep, `MicController` *drops* audio frames entirely so Deepgram receives (and bills) nothing. Pipecat's built-in worker idle timeout must stay `None` — with frames dropped, its default 300 s monitor would silently kill her.
- **Wake word is two-stage**: the custom `hey_aiva.onnx` model fires on TV/game speech with the same scores (up to 0.96) as real wakes, so a wake-word hit is only a *candidate*. `WakeWordListener` passes a 2.5 s pre-roll; `MicController` injects it ahead of live audio and holds the wake as provisional (`verifying`, `visibly_awake` False — eyes stay shut); `ActivityWatcher` confirms on the first final transcript containing her name (`mentions_name`) or rejects and puts her back to sleep, dropping the transcript before the LLM. Don't "simplify" this back to trusting the model score — see the `wake rejected` lines in the logs for what it filters.
- **Restart machinery**: `restart_self`/Ctrl+Alt+R exit with code 42; `start_aiva.bat` relaunches (or a detached watcher process does if she wasn't started via the bat). `.restart_marker` tells the next boot to say "I'm back" instead of a full intro. The avatar renderer stays up across restarts — the new process adopts it via `aiva/avatar_state.json`; only a real quit kills it.
- **Lip-sync timing**: TTS audio frames pass `LipSyncTap` FASTER than real-time (the output transport paces playback). RMS chunks are queued in the renderer with durations and consumed at wall-clock rate from `BotStartedSpeakingFrame`. Flush only on `InterruptionFrame` — flushing on `TTSStoppedFrame` (end of *generation*) would close her mouth mid-sentence every turn.
- **PyQt5, not PyQt6/PySide6**: the renderer's transparent window depends on it — Qt6 bindings have a known black-background bug with `WA_TranslucentBackground` + OpenGL (live2d-py issue #98).
- **Shell command safety is non-bypassable**: `run_command` only *stages* a command; execution requires the user's verbal confirmation followed by `confirm_pending_command`. Keep this two-step gate intact. The task runner obeys the same rule from the other side: a `shell` step pauses the task (`awaiting_user`, kind `confirm_command`) until `answer_task` brings a yes, and only then calls `tools.execute_shell` — the single place a command a model wrote actually runs. The runner's own fixed commands are the only exception and are never model-composed: `run_git` for worktree snapshots and the `repo_status` look tool, and `run_test_command` for the project's own pytest (user decision 2026-10-13; the `run_tests` look tool may only add test-file paths that `pick_test_targets` finds inside the project — never options). Looking needs no shell at all: the task agent's `LOOK_TOOLS` (`read_file`, `find_files`, `search_text`, `repo_status`, `run_tests`) are home-fenced and read-only, so the planner/agent prompts keep the shell for changes (2026-10-14: nine approvals for one verification). Writing a file is `create_file`, which never replaces an existing one unless `overwrite` is true (a taken name gets " (2)"), so the agent is told it's already approved; an agent that calls `step_failed` before trying any tool is sent back once (`pushed_back`). `search_text` skips `BINARY_EXTS` unopened (a repo search once read 1 GB of training audio). A task's question is answered only on a turn HE spoke in: `make_task_handlers(heard_him=)` (main.py: `link.current_turn.kind in user|both_second`) — she once said yes to nine of her own commands on her news turns. `run_command`/`confirm_pending_command`/`claude_code` are deliberately NOT in `RUNNER_TOOL_ALLOW`.
- **Reading is greenfield and cost-bounded**: study/synthesis run on `AIVA_STUDY_MODEL`/`AIVA_STUDY_SYNTH_MODEL` (default luna/terra — their OWN tokens-per-minute bucket, never the voice model); per-session and per-book (`AIVA_BOOK_MAX_COST_USD`=3) caps; a novel costs ~10-25 cents. `library.py` imports no sqlite (parse in a thread, write on the loop); `commit_section` is the ONLY place the book cursor moves, atomically with the note; quotes are verified verbatim ≤25 words and never enter the prompt. Books resume from a persisted cursor (they are NOT runner tasks); `book_memory.reconcile_stale()` only marks the in-flight session interrupted.
- **Reading changes her within bounds**: the static `PERSONALITY` traits are the floor; a book may deepen or add a facet, never contradict it (compatibility gate) — traits cap at 12, fade if unused, and a voice `drop_trait` removes one forever. Tell-once is announced-at-injection (rides the book-finish note); the four persona blocks all carry the anti-recite rule so she never lectures or quotes unprompted. Curiosity thresholds live in `becoming.CURIOSITY` and are tunable from the `becoming:`/`read:` log lines; `_user_present` uses Win32 GetLastInputInfo so she only asks to read when you're at the PC but quiet.
- **Task autonomy is experience-based by design** (user decision 2026-08-25): done-this-kind-of-thing-before → just do it with a one-line heads-up; novel, previously corrected, irreversible, shell or delegate → confirm first; options only when the planner flags genuinely different approaches. The voice LLM may be MORE careful than `decide_autonomy` says, never less. Don't re-tune the thresholds without checking `familiarity:` lines in the logs.
- **`answer_task` must find the task already waiting**: `TaskRunner._prepare_wait` puts a task into `awaiting_user` BEFORE `start_task` returns its in-turn question, because the user's yes can arrive in the same voice turn. Don't reorder that.
- **OpenAI tokens-per-minute is the scarce resource** (org is on the 30k TPM tier for gpt-4.1 as of 2026-08-26). Each voice turn re-sends the whole context + ~5.5k tokens of tool schemas + ~3.8k of system prompt. Keep side-calls OFF the voice model: `AIVA_TASK_MODEL` and `AIVA_VISION_MODEL` default to gpt-4.1-mini in `.env` (own bucket); `PatientOpenAILLMService`/`AIVA_LLM_MAX_RETRIES` make 429s a backoff instead of a dead turn; `trim_context()` (every 15 s in `flush_transcripts`, budget `AIVA_CONTEXT_BUDGET_CHARS`=24000) keeps history bounded — it saves transcripts first and calls `memory.forget_saved()` so persistence stays consistent, and never drops in-flight tool exchanges. Don't add per-turn LLM calls on the voice model without checking this.
- **Models are gpt-5.6-luna everywhere by default (voice, tasks, vision) since 2026-08-26** — 500k TPM at tier 1, ~$0.20/$1.20 per 1M, sub-second first token. The gpt-5.x line has a different Chat Completions shape: `max_tokens` is rejected (use `max_completion_tokens`) and function tools REQUIRE `reasoning_effort: "none"` (default effort → 400). Every direct OpenAI call goes through `utilities.llm_kwargs(model, max_tokens, temperature)`, and `main.py` builds the pipeline `Settings` with `max_completion_tokens` + `extra={"reasoning_effort": "none"}` for gpt-5.x. Never hand-write `max_tokens=` in a completion call. **gpt-6-luna is on the same shape** (`utilities.gpt5_shape`, verified live 2026-10-23: the old shape is a 400 on `max_tokens`); gpt-6.1-sol is deliberately not matched (it rejects effort `none`). Each sister's voice model is `Character.llm_model`: `AIVA_LLM_MODEL`, which Saga shares unless `SAGA_LLM_MODEL` is set (on the voice-upgrades branch Aiva runs gpt-6-luna and Saga stays on gpt-5.6-luna to compare). gpt-4.1 / gpt-4.1-mini shut down 2027-01-14, so they are no fallback any more; code defaults are gpt-5.6-luna. `LLM_RATES` in utilities.py must know any new model's price or the cost estimate falls back to mini rates.
- **The Bash tool un-escapes `\\n` in heredocs** on this machine — write patch scripts to files (Write tool) instead of inline `python - <<EOF` when the code contains backslash escapes.
- **`run_in_parallel` on the LLM service must stay True** (its default) — sequential mode defeats pipecat's call-grouping and makes her speak once per tool call instead of once per turn.
- **Elevation**: OBS carries a RUNASADMIN compat flag on this machine; it is launched with `__COMPAT_LAYER=RunAsInvoker` (see `launcher.py`) or launch fails with WinError 740.
- **pipecat is pinned at 1.5.0**; most online docs/examples cover the older 0.0.x API and don't match (imports, aggregators, worker/runner model differ). Trust the patterns in `main.py` over external examples.
- **File operations are fenced to the user profile** (`file_operations.resolve_path` rejects anything outside the home directory) — preserve that guardrail.
- Console prints can contain CJK (avatar hotkey names); stdout is reconfigured to UTF-8 with `errors="replace"` so a print can never crash a handler.
